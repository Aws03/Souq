# Souq: security control catalog

> One row per control that exists (or is missing) in this repository. Narrative and rationale: [Security.md](Security.md) · identity and permissions: [AuthenticationAndAuthorization.md](AuthenticationAndAuthorization.md) · isolation design: [MultiTenancy.md](../02-ARCHITECTURE/MultiTenancy.md).

## How to read this page

- **Status** is what the code does **today**:
  - **CURRENT** — implemented and (unless stated) covered by a test;
  - **PARTIAL** — implemented for part of the surface, or without the guarantee the name suggests. The gap is stated in the same row;
  - **PLANNED** — scheduled in [ProductRoadmap.md](../12-ROADMAP/ProductRoadmap.md) and **not implemented**. Items that are only an option, or were consciously postponed, are labelled FUTURE or DEFERRED instead.
- **Implementation** names stable paths and symbols, never line numbers.
- **Tests** names the test class that would fail if the control were removed. Test methods are Arabic; they are described in English here.
- A control's absence is as important as its presence. Section 12 collects every gap with a suggested remedy; each gap also appears in the row that owns it.

## 12. Gaps and risks

Ordered roughly by exposure. "Remedy" is a suggestion, not a commitment.

| # | Gap | Why it matters | Suggested remedy |
|---|---|---|---|
| G-01 | **No CI and no automated dependency scanning** (there is no `.github` directory or other pipeline in the repository) | Every control above is enforced by tests that only run when someone remembers to run them; a vulnerable dependency is found only by hand | Add a pipeline that runs `dotnet test` and the frontend tests on every push, plus `dotnet list package --vulnerable` and `npm audit` (PLANNED in Phase 20 as a dependency audit and Phase 23 as CI/CD) |
| G-02 | **No HTTPS in the shipped stack**, and the SPA's CSP is not yet enforced (SEC-HTTP-03, SEC-HTTP-04) | A deployment that forgets TLS silently breaks the `Secure` cookies and exposes tokens; a report-only CSP observes but does not block | Terminate TLS at the edge; confirm the SPA CSP in a browser (storefront **and** checkout) and rename the header to `Content-Security-Policy` |
| G-03 | **Bearer secrets in URLs reach the proxy's log** (SEC-LOG-07) | The API no longer logs the tracking token, but anyone with the web container's access log can still read reset, verification and invitation tokens from SPA page requests during their validity window | Disable or reformat the nginx access log for the SPA location in `frontend/nginx.conf`, or move those flows to a POST-then-redirect exchange |
| G-04 | **Logout does not end the access token** (SEC-AUTHN-11) | "Log out" on a shared machine leaves a working token for up to 15 minutes if it was captured | Rotate the security stamp on logout (it already invalidates everything) or accept it explicitly and document the window |
| G-05 | **Audit coverage is partial** (SEC-AUTHZ-10) | Order status changes, coupons, shipping methods and product create/update leave no `AuditEntries` row, so a store cannot reconstruct who changed a price or a coupon | Add `IAuditable` to those commands; the behavior does the rest |
| G-06 | **Lockout enables enumeration and targeted denial of service** (SEC-AUTHN-03) | An attacker can confirm an address exists and keep a specific customer locked out | Return the same code for locked and wrong-credential cases, and consider an IP-scoped delay instead of an account-scoped lock |
| G-07 | **Email verification is never required** (SEC-AUTHN-15) | Orders and notifications can be tied to an address nobody proved they own | Make it a store setting enforced at checkout, as Phase 3 intended, or state in the roadmap that it is out of scope |
| G-08 | **Rate limits are in-process and cover a narrow surface** (SEC-AUTHN-14) | Limits multiply by instance count; checkout, review posting and the webhook are unlimited | Move the limiter to a shared store when the app scales out; add limits to checkout and reviews |
| G-09 | **The application connects to SQL Server as `sa`** (`docker-compose.yml`) — Phase 0 finding B10, not scheduled in any phase | One SQL injection or one leaked connection string owns the whole instance, not just the application's data | Create a least-privilege login for the application and use it in the compose stack and in deployment |
| G-10 | **Migrations run at application startup** | A bad migration takes the API down and can race between instances | Move migrations to a deployment step with a migration bundle (PLANNED, Phase 23) |
| G-11 | **Secret rotation is manual with no re-wrap** (SEC-CFG-07) | The old key must live indefinitely, and removing it makes stores' payments fail with a 503 | Add a command that re-encrypts stored ciphertexts with the active key |
| G-12 | **Orphan uploads are never deleted** (SEC-UP-06) | Storage grows forever and removed images stay reachable by URL | Add a delete to `IFileStorage` and a sweep of unreferenced keys |
| G-13 | **Single-instance assumptions** — the stamp cache (30 s), the tenant directory cache (60 s) and the rate limiter are per process | Revocation and store suspension lag; limits weaken; correctness is unaffected | Shared cache or pub/sub invalidation before running more than one instance ([ADR-0022](../11-ADR/0022-tenancy-enforcement.md), [ADR-0023](../11-ADR/0023-sessions-and-credentials.md)) |
| G-14 | **No absolute refresh lifetime** and no "log out everywhere" | A stolen refresh token used regularly never expires | Add a family start timestamp and a maximum age (PLANNED, Phase 20 review); the account page adds global logout (PLANNED, Phase 16) |
| G-15 | **No MFA, no SSO** | High-value platform and store-admin accounts rest on one password | Adopt an external IdP behind the existing claims contract when a client needs it ([ADR-0010](../11-ADR/0010-authentication-authorization.md) revisit condition) |
| G-16 | **Minor-unit risk for three-decimal currencies (P-05)** (SEC-PAY-12) | A wrong multiplier charges a tenth of the price | Confirm the behaviour on the real Stripe account before enabling live payments in such a currency |
| G-17 | **The API port is published next to nginx and the trusted proxy range is wide** (SEC-HTTP-06) | Rate limiting and audit addresses can be influenced by a client that bypasses the proxy | Remove the published port in production; trust only the proxy's address |
| G-18 | **`frontend` still runs Vite 5** (Phase 0 finding B11's major upgrade was deferred to Phase 15, which shipped without it) | Development-server advisories stay open; not verified whether they still apply | Re-run `npm audit`, then upgrade in a dedicated change |
| G-19 | **No SQL Server Row-Level Security** | Isolation depends entirely on application-level filters and the write guard | Optional defence in depth, listed for Phase 20 |
| G-20 | **Registration discloses that an address exists** (`409 EmailTaken`) | Account enumeration on the registration route | Accept the trade-off explicitly, or answer generically and send a "you already have an account" email |
